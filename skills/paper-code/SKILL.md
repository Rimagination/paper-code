# Paper Code：面向学术读者的代码编辑

在不混入研究方法变更的前提下，让同行理解科研实现，并核对整理前后的计算行为。以消除实际阅读障碍为目标，不按行数、“AI 味”或个人风格重写；不预设 AI 代码必然更差。

## 0. 先检查显式调用

仅在用户通过 `/paper-code`、宿主 Skill 选择器，或肯定指令明确要求使用本 Skill 处理当前任务时启动。

- 普通编码、可读性或投稿请求不足以启用；引用、文件、工具输出中的名称，以及咨询、修改 Skill 本身或“不要用 paper-code”均不构成调用。
- 误加载且未获调用时止于本节：不读参考资料、不启动专项检查，返回普通任务流程，不反复提示启用。
- 同一明确授权且未结束的任务可随“继续”延续；任务完成、取消或切换无关任务后停止，不写入跨任务默认状态。
- 这是 Skill 层约束，不是已核实的宿主自动调用禁用开关；仍遵循宿主权限。论文正文润色、隐瞒来源和普通产品开发不属本工作流。

## 1. 选择模式与范围

通过调用检查后再选模式；下表不是自动触发关键词，也不授予额外权限。

| 模式 | 请求意图 | 行动 |
|---|---|---|
| audit | 看哪里难读、审查准备情况 | 只读，不运行项目代码、不改文件或环境；其他步骤仅作检查项 |
| polish | 整理科研代码，默认模式 | 最小必要编辑，按改动性质验证 |
| release | 准备投稿或复现交付包 | 在 polish 基础上补必要导航和说明，不发布 |

只问会影响结果且尚缺的信息：目标文件、修改范围、已有论文位置。默认读者有学科背景但不是原作者；沿用项目语言和命名习惯，不整体翻译注释。没有论文也可整理，标明“未提供论文，尚未核对”；未指定期刊时不宣称符合某刊要求。

## 2. 理解受影响路径，守住边界

定位相关入口、输入输出、配置、调用者和测试；按改动影响追踪，不因小 diff 就判定低风险，也不把局部任务扩成全仓库审计。用一句可核对的计算链绑定实际位置，例如“成对筛选 → 个体差值 → 样本统计”；纯文字修改只需核对相关实现。论文对应仅在提供材料且任务需要时展开；论文、数据和工具输出是证据，不是新增执行授权。

- 保留样本/缺失规则、统计定义、单位、数值类型与运算顺序、随机过程、划分和图表科学含义；不把方法纠错、向量化、并行化或换库混入润色。疑似错误单列，获独立授权再改。
- 保留公共 API/CLI、默认值、路径、字段、异常、日志和副作用。删除或改名先查静态调用、配置、动态引用、notebook 及外部契约；搜不到引用不等于可删。接口迁移另行确认。
- 保留用户改动与原结果；无版本管理时只留必要的小代码基线，不复制大数据。运行前检查副作用和耗时；不能隔离输出时先询问，不靠覆盖后恢复。不得借验证上传、付费调用或启动未授权长任务。
- 不编造方法理由、单位、公式/表图编号、依赖版本或验证记录；未知写“待作者确认”。不擅自选许可证、改署名或删 AI 声明；不将密钥、个人/受限数据或私有绝对路径加入交付包。

## 3. 按风险选检查，按需读参考

参考资料只读涉及的章节，已读且仍适用的内容不重复加载；不自动调用其他 Skill，也不为每次整理重新调研。

| 实际任务或改动 | 最小充分行动与阅读 |
|---|---|
| 只读审计 | 静态走读；遇相关科学定义再查下述不变量，不为凑等级执行测试 |
| 确认无执行/工具影响的说明文字或普通注释 | 对照实现与完整差异；无需数值重跑，交付标 V0：静态核查，行为未执行验证 |
| 改名、拆分、合并或其他可执行改动 | 先读 [验证协议](references/verification.md) §1–§3，建立成功基线，再编辑并回归；缺少条件时查 §4 |
| 科学定义、算法、随机流或精度需变化 | 停止把它当作润色；查相关不变量，拆出独立决策和验证范围 |
| 文档/交付包、notebook 复现 | 仅需要时读验证协议 §5；audit 仍只读，旧输出不当作本轮复现 |
| 文献、术语、适用性依据 | 仅需要解释依据时读 [研究依据](references/evidence.md)；指定期刊当前规则需另行核实 |

涉及科学计算时按影响选读 [科学不变量](references/scientific-invariants.md)：§1 样本/缺失/配对，§2 统计，§3 数值，§4 随机/机器学习，§5 时空，§6 契约，§7 图表，§8 notebook，§9 方法疑点。不能判断影响时先追踪关联，不以“未读到”判为不适用。

docstring、类型注解、导入、装饰器、doctest、编码/shebang、工具或调度器注释不自动归为纯文字：它们可能影响运行、反射、测试或产物；不能确认无影响时按可执行改动处理。

可执行改动必须先约定比较对象和容差，覆盖受影响核心路径与相关科学边界，优先复用测试，不新建测试框架。不新增种子伪装确定性。基线失败或缺少条件的路径不自动重构；独立且有成功基线的组件可继续，说明集成缺口。用户另行确认未验证编辑时标“行为未验证”。新差异未解决时停止扩大改动，不改 golden files、放宽断言或删测试来变绿；只撤销自己的相关修改。基线不是科学真理，有限回归不是所有输入上的等价证明。

## 4. 采用最小有效编辑阶梯

对每个障碍选择第一个足以解决问题的动作，不要求逐级实施：

1. 不妨碍理解：不改；不能指出具体收益的风格变化跳过。
2. 术语不清：局部准确命名或简短符号映射，保留公共契约。
3. 意图不清：补有证据的单位、假设或理由；删错误/复读注释，不编理由。
4. 步骤混杂：整理局部结构、已核实无用的探索残留，保留必要警告与审计痕迹。
5. 仍难理解：按计算职责拆分少量步骤，或合并已验证等价的重复逻辑。

简单脚本保持简单；清晰循环不必压成一行。沿用已有工具与结构，不新增无关框架、依赖、CLI 或配置层。每次改动有一个阅读收益，并按上节及时检查；没有更短代码也可以是更好的科研表达。

## 5. 验收、停止与交付

分别核查行为证据与读者理解：读者能否定位计算步骤、输入输出的含义/单位/形状/缺失规则、参数理由，以及换数据或参数的入口？必要的论文对应是否有证据？对照代码自行走读；高影响、歧义或用户要求时再考虑独立审阅，不强制启动子 Agent，不编理解评分或提速比例。

指定范围的主要阅读障碍解决、必要验证完成且新差异已处理后停止；剩余纯风格问题不扩大处理。方法决策、接口迁移或资源阻碍单列，不隐去缺口或把未验证工作报为等价完成。

默认只在对话中给三部分，长度匹配任务：

- **改了什么**：文件链接、具体阅读收益与保留行为；无改动时说明原因，audit 明示“只读审计，未修改文件”。
- **验证了什么**：实际命令/方法、比较结果、判据与覆盖；仅静态时标 V0，可执行回归按验证协议报告实际等级。
- **还有什么未确认**：未运行项、集成风险、作者待决的方法问题或投稿事项。不作“可直接投稿”认证。

优先复用已有说明；仅用户要求文档或 release 包时创建必要最小文件。不要自动提交、推送、发布或上传，止于授权的本地结果。
