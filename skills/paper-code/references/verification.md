# 验证协议：按改动风险选择证据

可执行改动读 §1–§3，遇阻碍读 §4，交付说明或 notebook 复现读 §5；§2 只展开实际比较对象。仅静态审计或已确认无执行/工具影响的文字修改可标 V0，不为提高等级增加运行。

区分“原流程有效性”和“整理前后一致性”：新旧一致不证明科学正确；解释准确、lint 或静态分数提高也不是执行等价的证据。

## 1. 基线与检查顺序

1. 检查受影响入口、调用者、现有测试、配置和环境；运行前确认副作用、耗时及授权。在独立输出位置建立基线，无法隔离时先询问。audit 不运行项目代码；用户另行授权执行时仅扩展到所准许的检查。
2. 记录原代码、输入/配置标识、实际命令、环境版本、输出和已有失败。大型数据只用安全版本标识或已有校验值，不为哈希扫描整盘或暴露敏感路径。
3. 优先复用已有检查；不足时在编辑前补少量针对性回归，覆盖受影响核心路径及相关边界，不引入测试框架。事先约定比较对象、容差和科学解释，保留已有种子而不新增种子伪装确定性。
4. 取得受影响路径的成功基线后做最小编辑，在同样输入、环境、配置下重复检查；范围扩展时补对应基线，不拿修改后输出自证。
5. 区分原有失败、环境问题和新差异。新差异先停相应路径，定位后修复自己的改动，或只回退自己的相关部分；不放宽容差、更新 golden files 或删断言来掩盖失败。

变量改名、提取函数和合并逻辑仍可能改变动态引用、求值顺序或异常，不能因 diff 小就免去基线。docstring/注解/导入/工具注释可能被程序消费；参见 [科学不变量](scientific-invariants.md) §6，无法确认无影响时同样走本节。

## 2. 按对象定义比较

- **结构与样本**：整数、计数、ID、布尔、分类通常精确相等；核对形状、列名、顺序和缺失位置，不靠排序掩盖配对或时序差异。
- **浮点数**：沿用已批准标准；预定绝对/相对误差并标参考方向，如 `abs(new - baseline) <= atol + rtol * abs(baseline)`。零附近需绝对误差，另查 NaN、正负无穷和 dtype；不向所有结果套同一容差。
- **统计输出**：核对估计值、标准误、区间、p 值、样本量和分组；数值达标仍要检查是否跨越作者指定的科学决策边界。
- **随机输出**：保留 RNG、种子、状态、调用次序/次数和配置；按需比较划分与采样索引。不能确定性复现时按领域预定的多次运行方案报告波动，一次相近不证明等价，不能挑种子。
- **文件与图表**：稳定结构可精确比较；先约定可忽略的非科学元数据。含时间戳等字段的文件哈希不能单独判定科学一致；图表先比底层数据、误差线、标签、尺度，再看渲染。
- **API/CLI**：核对参数、默认值、返回字段/顺序、错误类型/消息与退出码；内部命名不能破坏外部引用。纯文字编辑核对完整差异及消费者，不把未运行写成“测试通过”。

## 3. 如实选择验证等级

等级是本 Skill 的覆盖标签，不是认证或概率；按组件和实际证据报告，不强求升级。

| 等级 | 必要证据 | 允许表述 |
|---|---|---|
| V0 静态核查 | 阅读、文档对照或静态检查，没有成功执行前后比较 | “完成静态整理/审计，行为未执行验证” |
| V1 样例回归 | 改动前后同样的至少一个代表输入成功执行并比较 | “所测样例一致，未覆盖全部分析” |
| V2 定向回归 | 受影响核心流程及相关科学边界回归，按需核对输出/API/异常 | “所列测试与边界一致，不能推及未测输入” |
| V3 论文产物复现 | 同样数据/配置下比较改动前后所列正式表图/分析，另与论文目标产物核对数值和来源 | “已复现并核对所列论文产物”；部分产物逐项标状态 |

一个脚本达到 V3 不等于全仓库达到 V3；任何等级都不证明统计有效、因果正确、外部可推广或所有输入形式等价。实际使用形式验证时另报建模、假设、性质和工具范围。

## 4. 无法执行时的边界

- **依赖缺失**：报告缺失项与已知安装入口，不静默安装/升级环境。
- **数据受限**：继续静态审计；获授权后可用明确标注的合成边界样例验证局部，不能称原论文已复现。
- **算力不足**：优先已有低成本测试或可验证小样本；完整重跑命令与条件列为未运行，不凭旧输出报成功。
- **基线失败**：保留原有失败记录，不在润色中修 bug；该路径仅作只读分析和可核对、无执行影响的文档修正。独立且有成功基线的组件可继续，标明依赖关系与集成缺口。可执行的未验证编辑或方法纠错需另行确认范围，并明确交付状态。

## 5. 仅在需要时整理交付说明

用户要求文档或 release 包时，优先复用已有说明，必要信息集中表达：

- 研究用途、数据来源/申请方式、已核实环境与运行前提。
- 按顺序执行的命令、输入/参数/输出位置、代表输出与验证状态；方法/公式/表图 → 实现位置 → 命令的对应仅据实填写。
- 覆盖与限制，合成示例明确标注；不编 DOI、版本、运行时长或论文结果。不擅自选择许可证、改署名/AI 声明或宣称匿名审稿合规。

检查 notebook 执行顺序、隐藏状态和代码/旧输出是否一致；在授权资源与安全隔离副本中，从空内核顺序执行并与改前基线比较，需要声称 V3 时再核对论文产物。不能隔离输出、覆盖代价未知或资源未授权时不运行，明确未验证。audit 即使看到本节也不自动执行。

只检查拟交付范围，不把任务扩大为全盘扫描；发现密钥、个人或受限数据、私有绝对路径时报告，不擅自删除或发布。

## 6. 最小结果记录

默认在对话或已有日志中记录：检查范围/输入、实际命令或方法、基线与改后结果、预定判据、状态。只有多个结果需要比较时才用表格，不默认新建报告。

将状态分清为通过、未运行、不适用、原有失败、新差异；用“改了什么｜验证了什么｜还有什么未确认”交付，包含实际等级、覆盖缺口和作者待决事项。只做了静态核查就写 V0，不把没有数值重跑当作失败或运行成功。
